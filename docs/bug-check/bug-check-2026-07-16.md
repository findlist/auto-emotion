## 检查结论

本次检查共发现 **6 个 P0** 问题并全部修复通过验证，未发现新的 P1 需评估问题。

### 修复亮点

1. **shop_items 表 schema 全面对齐**：这是本轮最严重的 P0 簇——5 处 SQL 语句引用了 schema 中完全不存在的列（`price/price_type/emoji`），如果生产环境触发 ensureItemsExist 初始化分支或调用 getShopItems/buyItem/getUserInventory 中的任何一个，都会立即抛 `column "price"/"price_type"/"emoji" does not exist` 错误。但因 001_init.sql 第 344 行已用正确列名预填 9 个商品（ON CONFLICT DO NOTHING），实际生产环境的 ensureItemsExist 会因 COUNT > 0 直接跳过 INSERT，所以 INSERT 的 bug 不会触发，但 SELECT 的 bug 会立即触发。

2. **buyItem 货币分支错误**：这是最隐蔽的 bug——`SELECT *` 返回 schema 真实列，但代码后续依赖 `item.price_type` 字段判断扣金币还是钻石。由于 schema 无此列，`item.price_type` 永远是 undefined，所有商品都走 else 分支扣钻石（gems），导致用户购买金币商品时被错误扣除钻石（甚至钻石不足时抛"钻石不足"错误）。修复后通过 AS 别名让返回的 item 包含 price_type 字段。

3. **season-pass-service 字段清理**：延续 07-15 报告对 schema 一致性的清查，发现 season-pass-service 仍存在 users 表字段不匹配问题，本轮一并修复。
