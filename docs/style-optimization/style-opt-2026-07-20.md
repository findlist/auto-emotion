## 具体修改内容

### 1. 挂机页 · 武器/技能/宠物 emoji 圆形背景（idle.tsx）

**问题**：挂机页武器/技能/宠物卡片左侧的 emoji 图标（⚔️ / ✨ / 🐾）直接以 `text-3xl` 浮空展示，无任何背景容器。对比首页 header 的玩家头像（`w-12 h-12 rounded-full bg-pink`）与排行榜的排名奖牌（`w-10 h-10 rounded-full` + `medal-gold/silver/bronze`），这些圆形背景元素建立了"圆形主体识别区"的视觉模式。但挂机页装备卡片的 emoji 缺乏同等视觉权重，玩家扫视列表时 emoji 容易被卡片文字内容淹没，无法快速定位装备类型。

**修改**：3 处 emoji（武器 ⚔️ / 技能 ✨ / 宠物 🐾）均包裹进 `w-12 h-12 rounded-full` 圆形容器，背景色按装备状态差异化（已装备/已激活用 `bg-yellow/20` 或 `bg-mint/20` 呼应卡片边框色，未装备/未激活用 `bg-ink/5` 中性底）：

```diff
- <div className="flex items-center gap-3 mb-2">
-   {/* 装饰性 emoji,aria-hidden 避免与后跟武器名语义重复 */}
-   <span className="text-3xl" aria-hidden="true">⚔️</span>
-   <div className="flex-1">
+ <div className="flex items-center gap-3 mb-2">
+   {/* emoji 加圆形背景给视觉重量，与首页/挂机页 avatar 圆形头像视觉模式一致
+       已装备态用 yellow/20 呼应卡片黄色边框，未装备用 ink/5 中性底 */}
+   <div className={`w-12 h-12 rounded-full flex items-center justify-center flex-shrink-0 ${
+     isEquipped ? 'bg-yellow/20' : 'bg-ink/5'
+   }`}>
+     <span className="text-2xl" aria-hidden="true">⚔️</span>
+   </div>
+   <div className="flex-1">
```

技能与宠物卡片同款修改，分别用 `bg-mint/20`（已激活）和 `bg-yellow/20`（已装备）作为状态强调底色。

**设计原因**：
- **视觉模式一致性**：首页 header 玩家头像、排行榜排名奖牌、本页区域信息 chip 已建立"圆形主体识别区"视觉模式。emoji 圆形背景让装备卡片与这些既有元素视觉同源，整个应用的"主体识别"语言统一
- **状态色相呼应**：已装备/已激活态用 `bg-yellow/20` / `bg-mint/20` 与卡片边框色（`border-yellow` / `border-mint`）色相同源，强化状态视觉关联；未装备/未激活用 `bg-ink/5` 中性底避免色彩干扰
- **`flex-shrink-0`**：保护圆形容器不被长装备名挤压，保证 emoji 识别区始终完整
- **`text-2xl` 替代 `text-3xl`**：圆形容器已提供视觉权重，emoji 字号略微缩小避免与圆形边界冲突
- **`aria-hidden="true"` 保留**：emoji 为装饰性视觉标识，装备名通过文字朗读，避免冗余

### 2. 商店页 · 商品 + 背包道具 emoji 圆形背景（shop.tsx）

**问题**：商店页商品列表的 emoji（`text-4xl inline-block`）和背包列表的 emoji（`text-3xl`）均浮空展示，与挂机页 emoji 视觉权重问题同源。商品 emoji 虽有 `hover:scale-110` 微交互，但缺乏背景容器让缩放缺少基准点，hover 时 emoji 在空白处"漂浮"放大显得不稳定。背包道具 emoji 完全无交互反馈。

**修改**：商品 emoji 包裹进 `w-16 h-16 rounded-full bg-ink/5` 圆形容器（比装备卡片大一档，适配商品卡居中布局），hover 缩放从 emoji 本体转移到圆形容器：

```diff
- <div className="text-center mb-2">
-   {/* 商品 emoji 与后跟商品名语义重复，aria-hidden 屏蔽装饰图标 */}
-   <span className="text-4xl inline-block transition-transform hover:scale-110" aria-hidden="true">{item.emoji}</span>
- </div>
+ <div className="text-center mb-2">
+   {/* 商品 emoji 加圆形背景给视觉重量，与挂机页武器/技能/宠物图标视觉模式一致
+       hover 时 emoji 放大，圆形背景作为放大基准点让缩放更自然 */}
+   <div className="inline-flex w-16 h-16 rounded-full bg-ink/5 items-center justify-center transition-transform hover:scale-105">
+     <span className="text-4xl" aria-hidden="true">{item.emoji}</span>
+   </div>
+ </div>
```

背包道具 emoji 同款包裹进 `w-12 h-12 rounded-full bg-ink/5` 圆形容器，与商品列表保持一致视觉模式：

```diff
- <div className="flex items-center gap-3">
-   {/* 背包道具 emoji 与后跟道具名语义重复，aria-hidden 屏蔽装饰图标 */}
-   <span className="text-3xl" aria-hidden="true">{item.emoji}</span>
+ <div className="flex items-center gap-3">
+   {/* 背包道具 emoji 加圆形背景，与商品列表图标视觉模式一致 */}
+   <div className="w-12 h-12 rounded-full bg-ink/5 flex items-center justify-center flex-shrink-0">
+     <span className="text-2xl" aria-hidden="true">{item.emoji}</span>
+   </div>
```

**设计原因**：
- **同页视觉统一**：商品列表与背包列表的 emoji 现在共享圆形背景模式，整个商店页视觉语言一致
- **`w-16 h-16` 商品 + `w-12 h-12` 背包**：商品卡居中布局空间充裕用大一档圆形，背包卡水平布局紧凑用小一档，尺寸差异化适配不同布局密度
- **hover 缩放转移**：原 emoji 本体 `hover:scale-110` 改为圆形容器 `hover:scale-105`，缩放幅度更克制（110% → 105%），圆形容器作为缩放基准点让动效更稳定
- **`inline-flex` + `items-center justify-center`**：商品居中布局用 `inline-flex` 避免独占整行，背包水平布局用 `flex` 配合 `flex-shrink-0` 保护圆形不被挤压

### 3. 成就页 · 成就状态 emoji 圆形背景（achievements.tsx）

**问题**：成就卡片左侧的状态 emoji（🏆 已完成 / 🔒 未完成）以 `text-3xl` 浮空展示，与挂机页/商店页 emoji 视觉权重问题同源。成就页已用 `ach-bar-{type}` 左侧色条按成就类型区分色相，但状态 emoji（完成/未完成）缺乏视觉容器，玩家扫视长列表时难以快速定位"可领取"的成就。

**修改**：状态 emoji 包裹进 `w-12 h-12 rounded-full` 圆形容器，背景色按完成状态差异化（已完成用 `bg-mint/20` 呼应 `border-mint` 边框，未完成用 `bg-ink/5` 中性底）：

```diff
- <div className="flex items-start gap-3 mb-2">
-   {/* 成就状态 emoji（完成/未完成）为装饰性视觉标识，状态通过边框色、进度条、领取按钮多渠道传达，aria-hidden 屏蔽避免冗余朗读 */}
-   <span className="text-3xl" aria-hidden="true">
-     {achievement.completed ? '🏆' : '🔒'}
-   </span>
-   <div className="flex-1">
+ <div className="flex items-start gap-3 mb-2">
+   {/* 成就状态 emoji 加圆形背景：已完成用 mint/20 呼应 mint 边框，未完成用 ink/5 中性底
+       与挂机页武器/技能/宠物图标视觉模式一致 */}
+   <div className={`w-12 h-12 rounded-full flex items-center justify-center flex-shrink-0 ${
+     achievement.completed ? 'bg-mint/20' : 'bg-ink/5'
+   }`}>
+     <span className="text-2xl" aria-hidden="true">
+       {achievement.completed ? '🏆' : '🔒'}
+     </span>
+   </div>
+   <div className="flex-1">
```

**设计原因**：
- **状态色相呼应**：已完成态用 `bg-mint/20` 与卡片 `border-mint` 边框色相同源，强化"完成"视觉关联；未完成用 `bg-ink/5` 中性底不干扰进度条色彩
- **`items-start` 保留**：成就描述可能换行多行，圆形容器顶部对齐（`items-start`）避免容器垂直居中导致与多行文字错位
- **跨页视觉同源**：与挂机页武器/技能/宠物 emoji 圆形背景、商店页商品/背包 emoji 圆形背景形成跨页一致的"主体识别区"视觉模式

### 4. 任务页 · "可领取" badge 黄色脉冲（tasks.tsx）

**问题**：任务页"可领取"状态 badge（`bg-mint text-ink`）静态展示，与"进行中"（`bg-ink/20`）、"已领取"（`bg-ink text-cream/70`）三个状态在视觉重量上差异不大。玩家在 3-5 个任务的长列表中扫视时，可领取奖励的 badge 容易被忽略，导致奖励未及时领取。排行榜 Top1 已用 `animate-badge-pulse` 黄色光晕脉冲强调冠军位置，但任务页"可领取"这一玩家最关注的状态却未使用同款注意力引导。

**修改**：在"可领取"态 badge 上叠加 `animate-badge-pulse` 类，复用排行榜 Top1 同款 `badgePulse` 关键帧（`rgba(255, 217, 61, 0.6)` 黄色光晕）：

```diff
- <span
-   className={`font-mono text-xs px-2 py-1 shadow-[1px_1px_0_#1a1a1a] ${
-     status === 'claimed'
-       ? 'bg-ink text-cream/70'
-       : status === 'completed'
-       ? 'bg-mint text-ink'
-       : 'bg-ink/20 text-ink/70'
-   }`}
- >
+ {/* 状态标签：加阴影增强 Neo-brutalism 层次
+     "可领取"态叠加 animate-badge-pulse 黄色光晕脉冲，与排行榜 Top1 同款动画
+     设计原因：可领取奖励是玩家最关注的状态，原静态 mint badge 在长列表中容易被忽略；
+     黄色脉冲光晕（badgePulse 关键帧 rgba(255,217,61,0.6)）让"可领取"在视野中"呼吸"，
+     吸引玩家点击领取，与排行榜 Top1 冠军强调使用同一视觉语言 */}
+ <span
+   className={`font-mono text-xs px-2 py-1 shadow-[1px_1px_0_#1a1a1a] ${
+     status === 'claimed'
+       ? 'bg-ink text-cream/70'
+       : status === 'completed'
+       ? 'bg-mint text-ink animate-badge-pulse'
+       : 'bg-ink/20 text-ink/70'
+   }`}
+ >
```

**设计原因**：
- **同语义同视觉**：排行榜 Top1（冠军强调）与任务"可领取"（奖励强调）都是"玩家最应关注的位置"，语义相同应共享 `animate-badge-pulse` 视觉模式
- **复用既有 CSS 类**：`animate-badge-pulse` 与 `badgePulse` 关键帧已在 `index.css` 第 6 轮扩展中定义，无需新增 CSS，仅 JSX 引用
- **黄色光晕配色**：`badgePulse` 关键帧使用 `rgba(255, 217, 61, 0.6)`（yellow 半透明），与 mint badge 形成色相对比，脉冲时光晕从黄色淡出至透明，视觉上"呼吸"而不刺眼
- **`prefers-reduced-motion` 自动覆盖**：`badgePulse` 关键帧在 `@media (prefers-reduced-motion: reduce)` 下被全局规则覆盖为 `0.01ms`，前庭功能障碍用户不受脉冲干扰
- **克制使用范围**：仅"可领取"态叠加脉冲，"进行中"与"已领取"保持静态，避免长列表多 badge 同时脉冲造成视觉过载

- 任务"可领取"脉冲复用的 `animate-badge-pulse`（`badgePulse` 关键帧）已在 `@media (prefers-reduced-motion: reduce)` 下被全局规则覆盖为 `0.01ms`，前庭功能障碍用户不受影响
- emoji 圆形背景均为静态展示，无动画
- 商店商品 hover 缩放（`hover:scale-105`）属于交互反馈，在 reduced-motion 下过渡时长被覆盖为 `0.01ms` 即时切换

## 设计原则总结

本轮遵循以下原则：

1. **视觉模式补齐 > 新装饰堆砌**：4 处修改的本质都是"既有视觉模式在某些元素未落地"的修复——首页 header avatar、排行榜奖牌已建立"圆形主体识别区"视觉模式，但挂机/商店/成就页 emoji 缺乏同等视觉权重；排行榜 Top1 已用 `animate-badge-pulse` 强调冠军，但任务页"可领取"状态未使用同款注意力引导。补齐后整个应用的视觉语言更统一
2. **同语义同视觉**：圆形主体识别区适用于所有"主体识别"场景（avatar / 奖牌 / 装备图标 / 商品图标 / 状态图标），`animate-badge-pulse` 适用于所有"玩家最应关注"的场景（排行榜 Top1 / 任务可领取）。语义相同的元素用相同视觉模式，是设计系统的基础原则
3. **复用既有 CSS 类**：本轮零新增 CSS 工具类，全部复用前 9 轮已定义的 `animate-badge-pulse` 与 Tailwind 内置类（`bg-{color}/5`、`bg-{color}/20`、`rounded-full`、`flex-shrink-0`）。CSS 体积增长 0.04 kB 源自构建工具压缩微小变化而非新代码
4. **状态色相呼应**：已装备/已激活/已完成态的圆形背景色与卡片边框色同源（yellow/mint），未装备/未激活/未完成态用 ink/5 中性底避免色彩干扰。色彩语义在前 9 轮已建立，本轮在 emoji 背景上延伸应用
5. **功能零侵入**：所有修改限于样式层（className、JSX 结构），业务代码一字不动；新增的 `<div>` 均为纯视觉展示，不参与状态管理
6. **小步增量**：本轮 4 处改动（涉及 4 个文件，零 CSS 新增），每处独立可验证，遵循小步重构原则
