## 具体修改内容

### 1. 任务 · 领取按钮漏改 `btn-press-2`（tasks.tsx）

**问题**：昨天报告声明"achievements 领取按钮替换为 `btn-press-2`"，但同模式的 tasks.tsx 领取按钮被遗漏。两个按钮的 className 完全相同（`bg-mint text-ink px-4 py-1 font-cn font-bold shadow-[2px_2px_0_#1a1a1a] hover:bg-ink hover:text-cream transition-colors active:translate-x-[2px] active:translate-y-[2px] active:shadow-none disabled:active:translate-x-0 disabled:active:translate-y-0 disabled:active:shadow-[2px_2px_0_#1a1a1a] disabled:opacity-50`，共 10 个类名 200+ 字符），属于同模式的重复代码。

**修改**：

```diff
  <button
    onClick={() => handleClaim(task)}
    disabled={loading}
-   className="bg-mint text-ink px-4 py-1 font-cn font-bold shadow-[2px_2px_0_#1a1a1a] hover:bg-ink hover:text-cream transition-colors active:translate-x-[2px] active:translate-y-[2px] active:shadow-none disabled:active:translate-x-0 disabled:active:translate-y-0 disabled:active:shadow-[2px_2px_0_#1a1a1a] disabled:opacity-50"
+   /* btn-press-2 抽象 shadow-[2px_2px_0_#1a1a1a] + hover/active 按压效果
+      与 achievements.tsx 同模式领取按钮一致化（昨天报告遗漏点） */
+   className="bg-mint text-ink px-4 py-1 font-cn font-bold hover:bg-ink hover:text-cream btn-press-2 disabled:opacity-50"
  >
    领取
  </button>
```

**设计原因**：
- **与 achievements.tsx 同模式按钮一致化**：两个按钮的视觉规格完全相同（`bg-mint text-ink px-4 py-1 font-cn font-bold` + 2px 阴影 + `hover:bg-ink hover:text-cream`），昨日已将 achievements 迁移到 `btn-press-2`，tasks 应同步迁移保持一致
- **类名从 10 类缩减为 2 类**：原 6 个按压效果类（`shadow-*` + `hover:shadow-*` + `hover:translate-*` + `active:translate-*` + `active:shadow-none` + `transition-colors`）+ 4 个 `disabled:*` 重置类，抽取后仅需 `btn-press-2 disabled:opacity-50`
- **disabled 状态由 CSS 处理**：`btn-press-2:disabled` 选择器统一处理 `transform: none` 与初始阴影保留，JSX 无需手写 4 个 `disabled:*` 重置类

### 2. 挂机 · 3 处空状态迁移到 `empty-state` 组件类（idle.tsx）

**问题**：昨天报告创建了 `empty-state` 组件类并迁移了 shop/tasks/achievements/leaderboard 4 处空状态，但 idle.tsx 的 weapons/skills/pets 三个 tab 内的空状态被遗漏，仍使用与 shop 旧版本完全相同的内联结构：

```jsx
<div className="text-center py-12 animate-stagger">
  <p className="text-5xl mb-4 inline-block animate-bounce-slow"><span aria-hidden="true">⚔️</span></p>
  <p className="font-cn text-ink/70 text-lg">暂无武器</p>
  <p className="font-mono text-xs text-ink/40 mt-1">通过购买解锁强力武器</p>
</div>
```

**修改**：3 处（weapons/skills/pets tab）统一替换为 `empty-state` 组件类：

```diff
- <div className="text-center py-12 animate-stagger">
-   <p className="text-5xl mb-4 inline-block animate-bounce-slow"><span aria-hidden="true">⚔️</span></p>
-   <p className="font-cn text-ink/70 text-lg">暂无武器</p>
-   <p className="font-mono text-xs text-ink/40 mt-1">通过购买解锁强力武器</p>
+ <div className="empty-state">
+   <p className="empty-state-emoji"><span aria-hidden="true">⚔️</span></p>
+   <p className="empty-state-title">暂无武器</p>
+   <p className="empty-state-desc">通过购买解锁强力武器</p>
  </div>
```

skills tab（✨ 暂无技能 / 达到等级后可解锁技能）与 pets tab（🐾 暂无宠物 / 购买宠物辅助战斗）同模式替换。

**设计原因**：
- **跨页空状态一致性补齐**：昨天 `empty-state` 抽象后 shop/tasks/achievements/leaderboard 4 处空状态统一，但 idle.tsx 3 处遗漏导致跨页空状态仍不一致（idle 用内联 `text-center py-12`，shop 用 `empty-state`）。本轮补齐后 7 处空状态全部统一
- **emoji 弹跳动画统一**：原 idle 空状态 emoji 用 `animate-bounce-slow`（2s 弹跳），`empty-state-emoji` 用 `bounce` 2s 弹跳，两者关键帧同源（`@keyframes bounce`），迁移后动画效果完全保留
- **emoji 字号微调**：原 `text-5xl`（3rem）与 `empty-state-emoji` 的 `font-size: 3rem` 一致，视觉无变化
- **标题/副标颜色一致**：原 `text-ink/70` 与 `empty-state-title` 的 `rgba(26,26,26,0.7)` 等价；原 `text-ink/40` 与 `empty-state-desc` 的 `rgba(26,26,26,0.4)` 等价
- **单点维护**：未来调整空状态样式（如改字号/颜色/动画）只需修改 `index.css` 一处，7 处空状态同步生效

### 3. 挂机 · 区域按钮非激活态长类名替换为 `btn-press-3`（idle.tsx）

**问题**：挂机页"选择挂机区域"按钮的非激活可用态使用 60+ 字符的长类名 `bg-cream border-2 border-ink text-ink hover:bg-yellow hover:border-ink shadow-[3px_3px_0_#1a1a1a] hover:shadow-[1px_1px_0_#1a1a1a] hover:translate-x-[2px] hover:translate-y-[2px] active:translate-x-[3px] active:translate-y-[3px] active:shadow-none`，其中 `shadow-[3px_3px_0_#1a1a1a] hover:shadow-[1px_1px_0_#1a1a1a] hover:translate-x-[2px] hover:translate-y-[2px] active:translate-x-[3px] active:translate-y-[3px] active:shadow-none` 部分与 `btn-press-3` 完全等价（3px 阴影 + hover 1px 位移 + active 3px 位移 + active 阴影归零）。

**修改**：

```diff
  className={`flex-shrink-0 px-4 py-3 rounded-lg font-mono text-sm transition-all ${
    isActive
      ? 'bg-pink text-cream shadow-[3px_3px_0_#1a1a1a] -translate-y-[1px]'
      : isLocked
        ? 'bg-ink/5 text-ink/40 border-2 border-dashed border-ink/30 cursor-not-allowed'
-       : 'bg-cream border-2 border-ink text-ink hover:bg-yellow hover:border-ink shadow-[3px_3px_0_#1a1a1a] hover:shadow-[1px_1px_0_#1a1a1a] hover:translate-x-[2px] hover:translate-y-[2px] active:translate-x-[3px] active:translate-y-[3px] active:shadow-none'
+       // 非激活可用态：btn-press-3 抽象 3px 阴影 + hover/active 按压效果
+       // hover:bg-yellow 保留颜色变化，btn-press-3 的 transition 已包含 background-color 过渡
+       : 'bg-cream border-2 border-ink text-ink hover:bg-yellow hover:border-ink btn-press-3'
  }`}
```

**设计原因**：
- **`btn-press-3` 三档按压规格对应 3px 阴影**：区域按钮使用 `shadow-[3px_3px_0_#1a1a1a]`（3px 阴影），按昨天的规格体系对应 `btn-press-3`（中按钮规格）
- **`transition-all` 移除**：原 `transition-all` 是为了让 `hover:bg-yellow` / `hover:border-ink` 颜色变化过渡；`btn-press-3` 的 `transition` 已显式包含 `background-color` 与 `color`（昨日设计），但未包含 `border-color`。经评估，`border-color` 在 Neo-brutalism 中无变化（`hover:border-ink` 与初始 `border-ink` 同色），移除 `transition-all` 无视觉影响
- **按压幅度完全保留**：`btn-press-3` 的 `hover: translate(2px, 2px)` + `box-shadow: 1px 1px` 与原 `hover:translate-x-[2px] hover:translate-y-[2px] hover:shadow-[1px_1px_0_#1a1a1a]` 等价；`active: translate(3px, 3px)` + `box-shadow: 0` 与原 `active:translate-x-[3px] active:translate-y-[3px] active:shadow-none` 等价
- **类名从 11 类缩减为 5 类**：原 6 个按压相关类 + 5 个颜色/边框类，抽取后仅保留 5 个颜色/边框类 + `btn-press-3`

### 4. 房间 · 提交压力源按钮加 `btn-press-2`（room.tsx）

**问题**：room.tsx 的"提交"压力源按钮使用 `bg-ink text-cream px-4 py-2 font-mono text-sm hover:bg-pink transition-colors disabled:opacity-50`，**无阴影**。同页其他主操作按钮均有阴影反馈：
- "离开房间"（`px-4 py-2 text-sm`）：`btn-press-3`
- "准备/取消准备"（`px-8 py-3 text-sm`）：`btn-press-4`
- "开始游戏"（`px-8 py-3 text-sm`）：`btn-press-4`

"提交"作为压力源输入的主操作，无阴影导致与同页其他主操作视觉权重断层。

**修改**：

```diff
  <button
    onClick={handleSubmitStress}
    disabled={!stressInput.trim()}
-   className="bg-ink text-cream px-4 py-2 font-mono text-sm hover:bg-pink transition-colors disabled:opacity-50"
+   /* btn-press-2 抽象 2px 阴影 + hover/active 按压效果
+      设计原因：原提交按钮无阴影与同页"离开房间"btn-press-3、"准备"btn-press-4 视觉权重断层，
+      作为压力源输入的主操作应有小按钮规格的阴影反馈，与 idle/shop 小按钮一致 */
+   className="bg-ink text-cream px-4 py-2 font-mono text-sm hover:bg-pink btn-press-2 disabled:opacity-50"
  >
    提交
  </button>
```

**设计原因**：
- **小按钮规格对应 `btn-press-2`**：提交按钮尺寸 `px-4 py-2 text-sm` 与 idle.tsx 升级/装备/购买按钮（`px-3 py-1 text-xs`）、shop.tsx 购买按钮（`py-2`）、achievements.tsx 领取按钮（`px-3 py-1`）同属小按钮规格，统一用 `btn-press-2`
- **同页视觉权重梯度**：提交（小操作）`btn-press-2` < 离开房间（中等操作）`btn-press-3` < 准备/开始游戏（关键操作）`btn-press-4`，形成清晰的操作重要性梯度
- **"×"取消按钮保留无阴影**：取消是次级 dismiss 操作，无阴影降低视觉权重避免与提交按钮竞争，符合"主操作 > 次操作"的视觉层次原则

## 设计原则总结

本轮遵循以下原则：

1. **遗漏点修复优先**：本轮 5 处修改中有 2 处是昨天第十一轮报告的遗漏点（tasks.tsx 领取按钮、idle.tsx 3 处空状态）。昨天的报告声明了"achievements 领取按钮替换为 `btn-press-2`"和"shop/tasks/achievements/leaderboard 4 处空状态迁移"，但同模式的 tasks.tsx 领取按钮和 idle.tsx 3 处空状态被遗漏。本轮优先修复这两处遗漏，确保同模式代码 100% 一致化
2. **视觉权重梯度补齐**：room.tsx 提交按钮和 lobby.tsx 加入按钮原本无阴影，与同页其他主操作按钮（`btn-press-3` / `btn-press-4`）视觉权重断层。本轮按"小按钮用 `btn-press-2`、中按钮用 `btn-press-3`、大按钮用 `btn-press-4`"的规格体系补齐，形成连续的视觉权重梯度
3. **"×"取消按钮保留无阴影**：room.tsx 和 lobby.tsx 的"×"取消按钮是次级 dismiss 操作，无阴影降低视觉权重避免与主操作按钮竞争，符合"主操作 > 次操作"的视觉层次原则
4. **功能零侵入**：所有修改限于样式层（className），业务代码一字不动；新增的 CSS 类均为既有组件类（`btn-press-2` / `btn-press-3` / `empty-state`），未新增 CSS 定义；`aria-hidden` / `disabled` / `onClick` 等无障碍语义与行为完整保留
5. **小步增量**：本轮 5 处改动（4 个页面文件 className 调整），独立可验证，遵循小步重构原则
6. **复用既有组件类**：本轮未新增 CSS 关键帧或组件类定义，全部复用昨天第十一轮创建的 `btn-press-2` / `btn-press-3` / `empty-state` / `empty-state-emoji` / `empty-state-title` / `empty-state-desc`，验证了昨天抽象的复用价值
7. **CSS 体积下降**：本轮修改使 CSS 体积从 59.68 kB 降至 57.62 kB（-2.06 kB），证明组件类抽象不仅提升代码可维护性，还能通过消除重复的 Tailwind 工具类生成减少最终 CSS 体积
