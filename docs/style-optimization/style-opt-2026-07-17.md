## 具体修改内容

### 1. 挂机页 · weapons/skills/pets tab 补全空状态（idle.tsx）

**问题**：挂机页"武器 / 技能 / 宠物"三个 tab 在数据为空时仅显示一行标题（"武器库" / "技能书" / "宠物"），标题下方完全留白。玩家无法判断是"无数据"还是"加载中"，与 `shop.tsx`（暂无商品 🛒）、`tasks.tsx`（暂无任务 📋）、`achievements.tsx`、`leaderboard.tsx`（暂无数据 🏆）已建立的空状态模式不一致。

**修改**：为三个 tab 各添加空状态分支，沿用 `shop.tsx` 的空状态结构（emoji + 标题 + 副标），将原 `{items.map(...)}` 包裹为 `{items.length === 0 ? <空状态> : items.map(...)}` 三元表达式：

| Tab | emoji | 标题 | 副标 |
| --- | --- | --- | --- |
| weapons | ⚔️ | 暂无武器 | 通过购买解锁强力武器 |
| skills | ✨ | 暂无技能 | 达到等级后可解锁技能 |
| pets | 🐾 | 暂无宠物 | 购买宠物辅助战斗 |

**设计原因**：
- 与 `shop.tsx` 第 204-210 行、`tasks.tsx` 第 108-115 行、`leaderboard.tsx` 第 154-162 行的空状态结构完全一致：`text-center py-12 animate-stagger` 容器 + `text-5xl animate-bounce-slow` emoji + `font-cn text-ink/70 text-lg` 标题 + `font-mono text-xs text-ink/40 mt-1` 副标
- emoji 选择与 tab 标题 emoji 呼应（武器库 ⚔️ → 暂无武器 ⚔️、技能书 ✨ → 暂无技能 ✨、宠物 🐾 → 暂无宠物 🐾），保持视觉关联
- 副标提供引导性文案（"通过购买解锁" / "达到等级后可解锁" / "购买宠物辅助战斗"），告知玩家如何获取内容，不是单纯的"暂无数据"
- `aria-hidden` 屏蔽装饰性 emoji，避免屏幕阅读器冗余朗读
- 空状态使用 `animate-stagger` 入场，与列表项入场节奏一致

### 2. 挂机页 · 区域信息行重构为多色 chip（idle.tsx）

**问题**：挂机页"区域信息"原为单行文本，用 `·` 分隔三项信息：

```jsx
<p className="text-ink/70 font-mono text-xs">
  当前区域: <span className="text-ink font-bold">{status.area_name}</span> ·
  经验率 <span className="text-pink font-bold">{(status.exp_rate ?? 1) * 100}%</span> ·
  金币率 <span className="text-yellow font-bold">{(status.gold_rate ?? 1) * 100}%</span>
</p>
```

视觉层次弱，玩家难以一眼定位关键信息。同页的战力属性框（攻击/防御/生命/效率）已用 `bg-cream/10` + 4 色数值（orange/mint/pink/yellow）的色块化设计建立视觉层次，区域信息行未沿用此模式。

**修改**：将单行文本重构为 3 个独立 chip，每个 chip 用不同色相 + emoji + label + value：

| Chip | 底色 | 边框 | emoji | label | value 色 |
| --- | --- | --- | --- | --- | --- |
| 区域 | `bg-ink text-cream` | 无（深色主标识） | 📍 | 区域 | cream 白（继承） |
| 经验 | `bg-pink/15` | `border-pink/30` | ✨ | 经验 | pink 粉 |
| 金币 | `bg-yellow/20` | `border-yellow/40` | 💰 | 金币 | yellow 黄 |

容器从 `px-4 py-2 mb-2` + 单行 `<p>` 改为 `px-4 py-2 mb-2 flex flex-wrap gap-2`，让 3 个 chip 水平排列并在窄屏自动换行。

**设计原因**：
- **色相语义呼应**：区域用 ink 深色（主标识，最重要）、经验用 pink（核心成长指标，与首页头像 pink 呼应）、金币用 yellow（金币一贯用 yellow，与首页 💰 金币徽章一致）
- **chip 形态呼应**：rounded-full 胶囊 + 边框 + 浅色底的模式与 `shop.tsx` 商品价格徽章（`bg-yellow/20 border-yellow/40 rounded-full`）、`shop.tsx` 背包数量徽章（`bg-pink/10 border-pink/30 rounded-full`）一致，复用既有 chip 视觉语言
- **可扫描性提升**：3 个色块比单行文本更易扫读，玩家在切换挂机区域时可快速对比不同区域的经验/金币加成
- **flex-wrap 窄屏友好**：3 个 chip 在 375px 窄屏自动换行，不会溢出
- 区域 chip 加 `shadow-[2px_2px_0_#1a1a1a]` 硬阴影强化"主标识"地位，与 Neo-brutalism 硬阴影美学一致
- emoji 选择：📍（位置）、✨（经验/成长）、💰（金币）均为约定俗成的语义图标，aria-hidden 屏蔽避免冗余朗读

### 3. 战斗页 · loading 状态背景氛围 + 可读性修复（battle.tsx）

**问题**：战斗页 loading 状态容器为 `<div className="min-h-screen flex items-center justify-center">`，无任何背景类，继承 body 的 `bg-cream` 浅色背景。但内部使用的 `Loading` 组件（`components/Loading.tsx`）专为深色背景设计：

```tsx
// Loading.tsx 第 25 行
<div className={`${sizeMap[size]} border-4 border-cream border-t-pink rounded-full animate-spin`} />
// 第 29 行
<p className="font-mono text-sm text-cream/60">{text}</p>
```

spinner 用 `border-cream`（cream 色环）+ `border-t-pink`（粉色顶色），文字用 `text-cream/60`（60% 透明度 cream）。在 `bg-cream` 浅色背景上，cream 色环与 cream 文字几乎不可见，仅粉色顶色与"等待 AI 生成关卡数据..."文字勉强可辨，loading 状态可读性严重不足。

**修改**：loading 容器加 `bg-ink bg-glow-pink`：

```jsx
<div className="min-h-screen flex items-center justify-center bg-ink bg-glow-pink">
  <Loading size="lg" text="等待 AI 生成关卡数据..." />
</div>
```

**设计原因**：
- **可读性修复**：`bg-ink` 深色背景让 Loading 组件的 `border-cream` spinner 与 `text-cream/60` 文字恢复正常对比度，spinner 的 cream 色环 + pink 顶色旋转效果清晰可见
- **氛围层次**：`bg-glow-pink` 复用自 `login.tsx` / `register.tsx` / `home.tsx` header / `idle.tsx` header 的既有多色径向渐变（pink + mint 双色光晕），与 login/register 页深色氛围一致
- **沉浸感强化**：战斗页 loading 是"等待 AI 生成关卡"的关键等待期（最长 30s 超时），深色氛围比 cream 浅色更能传递"进入战斗"的前奏感，与后续 `game:level-ready` 后画布的 `0xfff8e7` cream 底色形成明暗对比，玩家从"暗黑等待"进入"明亮战场"的过渡更有戏剧性
- **零侵入**：仅修改容器 className，Loading 组件本身、`size="lg"` 参数、`text` 文案均不变；error 状态容器（`bg-cream`）保持原样不动

## 设计原则总结

本轮遵循以下原则：

1. **一致性优先**：挂机页空状态补全让 5 个列表页（shop/tasks/achievements/leaderboard/idle）的空状态结构完全统一，消除"4 页有空状态、1 页缺失"的体验断层
2. **复用既有模式**：区域信息 chip 复用 shop 页既有 chip 视觉语言（rounded-full + 浅色底 + 边框 + emoji），不引入新设计元素
3. **可读性修复 > 装饰**：battle loading 背景修改的本质是修复 Loading 组件在浅色背景上不可见的可读性 bug，深色氛围是修复后的副作用收益
4. **功能零侵入**：所有修改限于样式层（className、JSX 结构），业务代码一字不动
5. **小步增量**：本轮仅 3 处改动，每处独立可验证，遵循小步重构原则
