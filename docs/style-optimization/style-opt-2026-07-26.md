## 具体修改内容

### 1. 全局样式扩展 · 第十轮（index.css）

**问题**：本轮需要 4 个新视觉能力（背景氛围、导航边框、表单错误态、加载旋转器抽象），但既有 CSS 中无对应工具类。如果直接在 5+ 个页面中散落硬编码这些样式，将造成重复代码与跨页不一致风险。

**修改**：在 `src/index.css` 末尾追加第十轮样式扩展，新增 4 个工具类 / 组件类 + 1 个关键帧：

```css
/* ============ 第十轮样式优化扩展（视觉一致性 + 表单错误态 + 加载器抽象） ============ */
@layer utilities {
  /* 页面背景氛围：cream 底色叠加极淡对角条纹，统一 cream 页面氛围 */
  .bg-cream-atmos {
    background-color: var(--color-cream);
    background-image: repeating-linear-gradient(
      45deg,
      rgba(26, 26, 26, 0.025) 0,
      rgba(26, 26, 26, 0.025) 1px,
      transparent 1px,
      transparent 12px
    );
  }
}

@layer utilities {
  /* 顶部导航边框：3px 全不透明 pink，确保在 ink 深色底色上可见 */
  .nav-top-border {
    border-top: 3px solid var(--color-pink);
  }
}

@layer utilities {
  /* 表单错误态：pink 边框 + 极淡 pink 底色，让出错输入框自身有视觉反馈 */
  .input-error {
    border-color: var(--color-pink) !important;
    background-color: rgba(255, 61, 127, 0.04);
  }
}

@keyframes brutalSpin {
  to { transform: rotate(360deg); }
}

@layer components {
  /* 加载旋转器：抽象 5 处重复的 spinner 类名，统一风格便于维护 */
  .spinner-brutal {
    width: 2.5rem;
    height: 2.5rem;
    border: 4px solid rgba(26, 26, 26, 0.2);
    border-top-color: var(--color-pink);
    border-radius: 9999px;
    animation: brutalSpin 1s linear infinite;
  }
}
```

**设计原因**：
- **`@layer utilities` 收纳工具类**：`bg-cream-atmos` / `nav-top-border` / `input-error` 都是单一职责的样式覆盖，放入 utilities 层可被 Tailwind 内置类按需覆盖，保持层级清晰
- **`@layer components` 收纳 spinner**：`spinner-brutal` 是复合样式（尺寸 + 边框 + 圆角 + 动画），属于组件级抽象，放入 components 层与既有 `card-hover` / `scrollbar-brutal` 同层
- **`!important` 仅用于 input-error**：错误态需要覆盖 Tailwind 的 `border-2 border-ink` 默认边框色，`!important` 是必要的优先级提升；其他类均通过层级顺序自然生效，不滥用 `!important`
- **`rgba(26, 26, 26, 0.025)` 极淡对角条纹**：背景氛围不能喧宾夺主，0.025 透明度的 1px 对角线在 12px 间距下形成微妙纹理，远观近于纯色，近看有质感
- **`brutalSpin` 关键帧独立定义**：与 Tailwind 内置 `animate-spin` 的 `--tw-spin` 体系解耦，避免被 Tailwind 升级影响

### 2. 首页 · 底部导航边框可见性修复（home.tsx）

**问题**：首页底部主导航 `<nav>` 使用 `border-t-3 border-pink/30`，但 nav 底色是 `bg-ink`（深色），`pink/30`（30% 透明度的 pink）在 ink 上几乎不可见，导致导航与主内容区分隔模糊，玩家难以感知导航边界。

**修改**：

```diff
- <nav aria-label="主导航" role="navigation" className="bg-ink text-cream px-2 sm:px-4 py-2 flex justify-around sticky bottom-0 border-t-3 border-pink/30">
+ <nav aria-label="主导航" role="navigation" className="bg-ink text-cream px-2 sm:px-4 py-2 flex justify-around sticky bottom-0 nav-top-border">
```

**设计原因**：
- **`nav-top-border` 替代 `border-pink/30`**：3px 全不透明 pink 在 ink 底色上对比度足够，玩家可清晰感知导航边界
- **保留 `border-t-3` 语义但提升可见性**：原 `border-t-3 border-pink/30` 表达"顶部 3px pink 边框"，`nav-top-border` 表达相同语义但用全不透明色，符合"语义不变、视觉强化"原则
- **复用全局类**：抽取为 `nav-top-border` 后，未来其他页面需要顶部导航边框可复用，避免散落硬编码

### 3. 大厅 / 房间 / 战斗 · 背景氛围统一（lobby.tsx / room.tsx / battle.tsx）

**问题**：lobby/room/battle 三个页面根容器使用 `bg-cream` 纯色背景，但项目内其他 cream 底色页面（如 shop/tasks/achievements/leaderboard/season-pass）的 cream 背景已通过 `bg-cream-atmos` 或类似氛围类叠加纹理。三个游戏核心页面缺少背景氛围，与同调色板页面氛围脱节，纯色背景在大屏上显得空洞。

**修改**：三个页面根 `<div>` 的 `className` 添加 `bg-cream-atmos`：

```diff
- <div className="min-h-screen flex flex-col items-center justify-center p-8 scrollbar-brutal">
+ <div className="min-h-screen flex flex-col items-center justify-center p-8 scrollbar-brutal bg-cream-atmos">
```

```diff
- <div className="min-h-screen flex flex-col items-center p-8 scrollbar-brutal">
+ <div className="min-h-screen flex flex-col items-center p-8 scrollbar-brutal bg-cream-atmos">
```

```diff
- <div className="min-h-screen flex flex-col items-center justify-center p-4 gap-4 scrollbar-brutal">
+ <div className="min-h-screen flex flex-col items-center justify-center p-4 gap-4 scrollbar-brutal bg-cream-atmos">
```

**设计原因**：
- **跨页氛围统一**：lobby/room/battle 是玩家高频停留的核心页面，背景氛围应与其他 cream 页面一致，避免玩家在页面间跳转时感知到背景"忽纯忽纹"的不一致
- **`bg-cream-atmos` 替代 `bg-cream`**：保留 cream 底色（`background-color: var(--color-cream)`）的同时叠加极淡对角条纹，远观近于纯色，近看有质感，不喧宾夺主
- **不改变布局**：仅替换背景类，`min-h-screen` / `flex` / `p-8` 等布局类完整保留，页面结构零变化

### 4. 登录 / 注册 · 表单错误态视觉反馈（login.tsx / register.tsx）

**问题**：login/register 表单出错时（如手机号格式错误、密码不一致），仅错误消息块（`bg-pink/10` 背景）变色，输入框本身保持默认 `border-2 border-ink` 状态。用户需要扫描整个表单才能定位出错字段，错误反馈不直观。对比 achievements/tasks 页面的状态色边框（`border-mint` / `border-ink`），登录注册表单缺少同等错误态视觉反馈。

**修改**：在所有输入框的 `className` 中添加条件类 `${error ? 'input-error' : ''}`：

```diff
  <input
    id={phoneId}
    type="tel"
    value={phone}
    onChange={(e) => setPhone(e.target.value)}
    placeholder="请输入手机号"
    aria-invalid={error ? true : undefined}
    aria-describedby={error ? errorId : undefined}
-   className="w-full px-4 py-3 border-2 border-ink font-mono text-sm focus:border-pink focus:outline-none input-focus-pink transition-all"
+   className={`w-full px-4 py-3 border-2 border-ink font-mono text-sm focus:border-pink focus:outline-none input-focus-pink transition-all ${error ? 'input-error' : ''}`}
    required
    minLength={11}
    maxLength={20}
  />
```

login.tsx 共修改 2 处输入框（手机号、密码），register.tsx 共修改 4 处输入框（手机号、昵称、密码、确认密码）。

**设计原因**：
- **错误态视觉反馈链路完整**：原仅"错误消息块变色"是单点反馈，新增"输入框 pink 边框 + 极淡 pink 底色"后，出错字段自身有视觉反馈，用户无需扫描整个表单即可定位
- **`input-error` 复用全局类**：抽取为 `input-error` 后，login/register 共享同一错误态样式，未来其他表单页面（如修改密码、绑定手机）可复用
- **`!important` 覆盖 `border-ink`**：`input-error` 内 `border-color: var(--color-pink) !important` 必要地覆盖 `border-2 border-ink` 默认边框色，确保错误态边框色优先级
- **`rgba(255, 61, 127, 0.04)` 极淡底色**：错误态底色不能喧宾夺主，0.04 透明度的 pink 在 cream 底色上形成微妙红调，与 pink 边框协同但不刺眼
- **保留既有 `aria-invalid` / `aria-describedby`**：错误态的 ARIA 语义完整保留，屏幕阅读器仍可朗读错误信息；`input-error` 仅是视觉强化，不影响无障碍语义

### 5. 商店 / 任务 / 成就 / 排行榜 / 赛季通行证 · 加载旋转器抽象（shop/tasks/achievements/leaderboard/season-pass）

**问题**：5 个页面的加载旋转器使用完全相同的类名 `w-10 h-10 border-4 border-ink/20 border-t-pink rounded-full animate-spin`（shop 多一个 `inline-block`），未抽取复用。这是典型的重复代码：任何 spinner 样式调整（如尺寸、颜色、动画速度）都需要 5 处同步修改，维护成本高且易遗漏。

**修改**：将 5 处加载旋转器的 `className` 替换为 `spinner-brutal`（shop 保留 `inline-block` 修饰）：

```diff
- <div className="w-10 h-10 border-4 border-ink/20 border-t-pink rounded-full animate-spin" />
+ <div className="spinner-brutal" />
```

```diff
- <div className="inline-block w-10 h-10 border-4 border-ink/20 border-t-pink rounded-full animate-spin" />
+ <div className="spinner-brutal inline-block" />
```

**设计原因**：
- **DRY 原则**：5 处完全相同的类名抽取为 `spinner-brutal` 组件类，消除重复代码，未来调整 spinner 样式只需修改 `index.css` 一处
- **`spinner-brutal` 命名与既有约定一致**：与 `scrollbar-brutal` / `card-hover` 等 Neo-brutalism 风格组件类命名同源，`-brutal` 后缀标识设计风格
- **尺寸微调**：原 `w-10 h-10`（2.5rem）与 `spinner-brutal` 的 `width/height: 2.5rem` 完全一致，视觉无变化
- **`border-4` 保留**：`spinner-brutal` 内 `border: 4px solid` 与原 `border-4` 一致，旋转器视觉粗细不变
- **`border-t-pink` 保留**：`spinner-brutal` 内 `border-top-color: var(--color-pink)` 与原 `border-t-pink` 一致，旋转器主色不变
- **`animate-spin` 替换为 `brutalSpin`**：`brutalSpin` 关键帧与 Tailwind 内置 `animate-spin` 视觉效果一致（1s linear infinite），但与 Tailwind 升级解耦，避免被 `--tw-spin` 变量体系影响
- **shop 保留 `inline-block`**：shop 的 spinner 在 flex 容器内需要 `inline-block` 才能正确居中，作为修饰类追加在 `spinner-brutal` 之后，符合 BEM 修饰类思路

- `bg-cream-atmos` 的对角条纹为静态背景，无动画
- `nav-top-border` 为静态边框，无动画
- `input-error` 为静态边框 + 底色，无动画
- 前庭功能障碍用户不受影响

## 设计原则总结

本轮遵循以下原则：

1. **视觉一致性优先**：lobby/room/battle 三个核心页面与同调色板页面（shop/tasks/achievements/leaderboard/season-pass）背景氛围脱节是本轮最重要的修复。玩家在页面间跳转时感知到的"背景忽纯忽纹"是不一致感的来源，统一为 `bg-cream-atmos` 后整个应用的 cream 底色页面氛围完全统一
2. **可见性优先于"克制"**：首页底部导航 `border-pink/30` 在 ink 深色底色上几乎不可见，这是"克制"过头的案例。`nav-top-border` 用全不透明 pink 提升可见性，符合 Neo-brutalism"强烈视觉对比"的设计语言
3. **错误态视觉反馈链路完整**：表单出错时仅错误消息块变色是单点反馈，输入框本身也需要视觉反馈。`input-error` 让出错字段自身有 pink 边框 + 极淡 pink 底色，错误反馈链路从"单点"扩展为"字段 + 消息"双点，用户定位出错字段效率提升
4. **DRY 原则消除重复**：5 处完全相同的 spinner 类名是典型的重复代码，抽取为 `spinner-brutal` 后消除重复，未来调整 spinner 样式只需修改 `index.css` 一处。这与既有的 `scrollbar-brutal` / `card-hover` 等 Neo-brutalism 组件类抽象思路一致
5. **功能零侵入**：所有修改限于样式层（className、index.css 工具类 / 组件类定义），业务代码一字不动；新增的 CSS 类均为纯视觉展示，不参与状态管理
6. **小步增量**：本轮 12 处改动（1 个 CSS 文件扩展 + 11 个页面 className 调整），独立可验证，遵循小步重构原则
7. **`@layer` 分层清晰**：工具类（`bg-cream-atmos` / `nav-top-border` / `input-error`）放入 `@layer utilities`，组件类（`spinner-brutal`）放入 `@layer components`，与既有样式系统分层约定一致
