## 具体修改内容

### 1. 首页 · 背景图柔和遮罩（home.tsx）

**问题**：首页根容器直接使用 `bg-[url('/llq.jpg')] bg-cover bg-center`，背景图色彩繁复、明暗不均。Neo-brutalism 卡片间隙处图片噪声分散注意力，与硬边硬阴影的卡片风格冲突，雷达卡 / 主入口按钮 / 功能网格等核心内容的视觉层次被背景图稀释。

**修改**：根容器加 `bg-image-soft-mask` 工具类，通过 `::before` 伪元素叠加 `rgba(255, 248, 231, 0.75)` cream 半透明遮罩，子元素相对定位（`z-index: 1`）提升至遮罩之上：

```diff
- <div className="min-h-screen flex flex-col max-w-2xl mx-auto scrollbar-brutal bg-[url('/llq.jpg')] bg-cover bg-center">
+ <div className="min-h-screen flex flex-col max-w-2xl mx-auto scrollbar-brutal bg-[url('/llq.jpg')] bg-cover bg-center bg-image-soft-mask">
```

新增 CSS 工具类（`src/index.css` 第 9 轮扩展）：

```css
@layer components {
  .bg-image-soft-mask { position: relative; }
  .bg-image-soft-mask::before {
    content: '';
    position: absolute;
    inset: 0;
    background-color: rgba(255, 248, 231, 0.75);
    pointer-events: none;
    z-index: 0;
  }
  .bg-image-soft-mask > * {
    position: relative;
    z-index: 1;
  }
}
```

**设计原因**：
- **不删除背景图**：llq.jpg 作为首页氛围暗示仍有价值，纯 cream 底色会让首页与挂机/商店等列表页过于同质化
- **0.75 透明度平衡**：cream/75 让背景图隐约可辨（约 25% 显隐）但不喧宾夺主，卡片硬阴影重新成为主导视觉元素
- **`::before` + `pointer-events:none`**：不阻挡子元素交互，不破坏既有布局
- **子元素自动提升 z-index**：通过 `> *` 选择器让所有直接子元素相对定位至遮罩之上，避免逐个加 `relative z-10` 的侵入式修改

### 2. 首页 · 装饰卡去除伪交互（home.tsx）

**问题**：首页"快捷入口三联"（每日奖励 / 排行榜 / 武器库）为 `<div>` 元素，无 `onClick` 处理器，但原挂 `card-hover` 类后 hover 时卡片浮起扩大阴影，视觉上暗示"可点击"但实际无响应，造成认知断层。下方"更多功能"6 个 `<button>` 才是真正的可交互入口，两类卡片视觉权重相同导致主次混淆。

**修改**：3 张装饰卡移除 `card-hover`，阴影从 `shadow-[3px_3px_0_#1a1a1a]` 减至 `shadow-[2px_2px_0_#1a1a1a]`：

```diff
- <div className="bg-yellow text-ink p-2 sm:p-3 rounded-lg text-center shadow-[3px_3px_0_#1a1a1a] card-hover">
+ <div className="bg-yellow text-ink p-2 sm:p-3 rounded-lg text-center shadow-[2px_2px_0_#1a1a1a]">
```

（3 张卡片均做相同修改）

**设计原因**：
- **去除 hover 反馈**：`card-hover` 的浮起效果是"可交互"的核心视觉信号，无 onClick 的元素不应携带此信号
- **降低阴影权重**：从 3px 减至 2px，与下方"更多功能"按钮的 4px 阴影形成主次区分，让真正的可交互入口视觉权重更高
- **保留装饰功能**：3 张卡片仍作为"功能预览"展示游戏内容（每日奖励 🎁 / 排行榜 🏆 / 武器库 📦），仅去除误导性交互反馈
- **不删除卡片**：避免破坏首页视觉密度，3 色卡片（yellow/orange/pink）作为色彩节奏过渡仍有价值

### 3. 成就页 · 统计条进度可视化（achievements.tsx）

**问题**：成就页统计栏原为纯文字"已完成 X 个 | 已领取 Y 个奖励"，玩家无法一眼感知整体完成进度。需要心算 `completedCount / achievements.length` 才能知道还差多少，认知负担大。

**修改**：统计栏内嵌 4px 高迷你进度条，黄色填充表示完成比例：

```jsx
<div className="bg-pink text-cream px-4 py-3 border-b-2 border-ink">
  <p className="font-cn text-sm">
    已完成 <span className="font-bold text-yellow">{completedCount}</span> 个 | 已领取 <span className="font-bold text-yellow">{claimedCount}</span> 个奖励
  </p>
  {achievements.length > 0 && (
    <div
      className="mini-progress"
      role="progressbar"
      aria-label="成就完成进度"
      aria-valuenow={completedCount}
      aria-valuemin={0}
      aria-valuemax={achievements.length}
    >
      <div
        className="mini-progress-fill"
        style={{ width: `${(completedCount / achievements.length) * 100}%` }}
      />
    </div>
  )}
</div>
```

新增 CSS 工具类：

```css
@layer components {
  .mini-progress {
    height: 4px;
    background: rgba(255, 248, 231, 0.3);
    border-radius: 2px;
    overflow: hidden;
    margin-top: 6px;
  }
  .mini-progress-fill {
    height: 100%;
    background: var(--color-yellow);
    border-radius: 2px;
    transition: width var(--duration-slow) ease-out;
  }
}
```

**设计原因**：
- **颜色呼应**：黄色填充与统计文字 `text-yellow` 数字色一致，形成"数字 + 进度"的视觉单元
- **4px 高度克制**：迷你进度条不喧宾夺主，作为文字的视觉补充而非主导元素
- **`role="progressbar"` + aria 属性**：屏幕阅读器可朗读"成就完成进度 X/Y"，视障用户也能感知进度
- **`achievements.length > 0` 守卫**：空成就列表时不渲染进度条，避免 0/0 除法与无意义空进度条
- **`transition: width 400ms`**：进度变化时平滑动画，让"领取奖励后完成数 +1"的反馈更具仪式感
- **背景色 `cream/30`**：在 pink 统计条上形成可见轨道，对比度足够区分填充与未填充部分

### 4. 房间页 · 玩家就绪状态指示器（room.tsx）

**问题**：房间页玩家列表每行仅靠右侧文字"✓ 已准备 / 未准备"区分状态，房主需要逐行阅读文字才能统计已准备人数，4-8 人房间下扫视效率低。原左侧仅有首字母 avatar（颜色区分房主/自己/他人），无就绪状态视觉锚点。

**修改**：每个玩家行左侧（avatar 之前）加 8px 圆点，按状态分色：

```jsx
<span
  aria-hidden="true"
  className={`ready-dot ${
    player.userId === roomStore.hostId
      ? 'ready-dot-host'
      : player.isReady
      ? 'ready-dot-ready'
      : 'ready-dot-pending'
  }`}
/>
```

新增 CSS 工具类：

```css
@layer components {
  .ready-dot {
    width: 8px;
    height: 8px;
    border-radius: 50%;
    flex-shrink: 0;
    box-shadow: 0 0 0 2px var(--color-cream);
  }
  .ready-dot-ready {
    background: var(--color-mint);
    box-shadow: 0 0 0 2px var(--color-cream), 1px 1px 0 0 var(--color-ink);
  }
  .ready-dot-pending {
    background: rgba(26, 26, 26, 0.35);
    box-shadow: 0 0 0 2px var(--color-cream);
  }
  .ready-dot-host {
    background: var(--color-yellow);
    box-shadow: 0 0 0 2px var(--color-cream), 1px 1px 0 0 var(--color-ink);
  }
}
```

**设计原因**：
- **三色编码**：yellow=房主（特殊身份优先级最高，房主无需准备）、mint=已准备（积极状态）、ink/35=未准备（中性待办）
- **与既有色彩语义一致**：mint 在任务/成就页表示"可领取"、挂机页表示"防御"、battle HUD 表示"档位"，"积极/就绪"语义贯穿全应用
- **`box-shadow: 0 0 0 2px cream`**：白色外环让圆点在任意卡片底色（cream / yellow/20）上都清晰可见
- **`aria-hidden="true"`**：圆点为纯装饰，状态通过右侧文字"✓ 已准备 / 未准备"朗读，避免冗余
- **位于 avatar 之前**：形成"状态 → 身份 → 名字"的从左到右信息层次，符合阅读习惯
- **与挂机 attr-bar / 任务 task-bar / 成就 ach-bar 同源**：整个应用已建立"颜色编码状态"的设计模式，圆点是该模式在房间页的延伸

### 5. 登录 / 注册页 · 表单分隔虚线（login.tsx, register.tsx）

**问题**：登录 / 注册表单底部"立即注册 / 立即登录"切换链接直接跟在提交按钮下方，无视觉分隔。用户混清"主操作（提交登录/注册）"与"次要切换（去另一页面）"的层级，特别是登录失败时错误提示、提交按钮、切换链接三者堆叠，视觉层次混乱。

**修改**：切换链接容器加 `mt-6 pt-4 divider-dashed`，上方加 2px 虚线分隔：

```diff
- <div className="mt-6 text-center">
+ <div className="mt-6 pt-4 divider-dashed text-center">
```

新增 CSS 工具类：

```css
@layer utilities {
  .divider-dashed {
    border-top: 2px dashed rgba(26, 26, 26, 0.25);
  }
}
```

**设计原因**：
- **虚线 vs 实线**：虚线比实线轻量，表示"次要分隔"而非"硬性边界"，不喧宾夺主
- **ink/25 透明度**：在 cream 表单卡背景上清晰可见但不刺眼，与 Neo-brutalism 硬边风格形成"主硬（border-4 border-ink）+ 次软（虚线 ink/25）"的层次
- **`mt-6 pt-4` 组合**：`mt-6`（24px）保持与提交按钮的呼吸距离，`pt-4`（16px）让虚线与下方文字有舒适间距
- **登录/注册对称**：两页同步修改，保持视觉一致性，避免用户在两页间切换时感受断层
- **不破坏原有 hover/下划线交互**：切换链接按钮的 `hover:underline decoration-2 underline-offset-2` 完全保留

## 设计原则总结

本轮遵循以下原则：

1. **氛围层次修复 > 装饰堆砌**：首页背景图遮罩的本质是修复"图片噪声稀释卡片层次"的视觉 bug，而非添加新装饰；遮罩保留背景图氛围暗示同时让卡片回到主导地位
2. **UX 一致性优先**：装饰卡去除 `card-hover` 修复"看起来可点击但无响应"的认知断层，让真正的可交互入口独占交互预期
3. **颜色编码状态模式延伸**：房间页 `ready-dot` 是挂机 attr-bar / 任务 task-bar / 成就 ach-bar 的"颜色编码状态"模式在房间页的延伸，整个应用的设计语言更统一
4. **复用既有色彩语义**：mini-progress 用 yellow（与统计文字数字色一致）、ready-dot-ready 用 mint（与任务/成就"可领取"色一致）、ready-dot-host 用 yellow（与房主标签色一致），不引入新色相
5. **功能零侵入**：所有修改限于样式层（className、JSX 结构），业务代码一字不动；新增的 `<span>` / `<div>` 均为纯装饰或进度展示，不参与状态管理
6. **小步增量**：本轮 5 处改动（涉及 6 个文件 + 1 个 CSS），每处独立可验证，遵循小步重构原则
