## 具体修改内容

### 1. 战斗页 · 结算弹窗 Top3 奖牌化（battle.tsx）

**问题**：排行榜页 Top1/2/3 用 `medal-gold/silver/bronze` 圆形奖牌 + `medal-shine` 光泽动画（金/银/铜金属质感），视觉重量突出冠军位置；但战斗结算弹窗的 Top3 排名仅用文字色区分（`text-yellow` / `text-ink/50` / `text-orange`），同样是 Top3 排名展示，视觉语言不一致。玩家在两页间切换时感受断层：排行榜的"冠军金"是金属奖牌，结算弹窗的"冠军金"只是文字色。

**修改**：结算弹窗每行左侧加 7×7 圆形奖牌 badge，复用排行榜同款 `medal-gold/silver/bronze` + `medal-shine` 类；4+ 名用 cream + ink/30 边框作为"未获奖"中性态：

```diff
- // 前三名奖牌色：与排行榜保持一致的金/银/铜
- // 银/铜改用 ink 灰阶与 orange，避免 gray-400/amber-700 脱离 Neo-brutalism 调色板
- const medalClass = (idx: number) => {
-   if (idx === 0) return 'text-yellow';
-   if (idx === 1) return 'text-ink/50';
-   if (idx === 2) return 'text-orange';
-   return 'text-ink';
- };
+ // 前三名奖牌样式：与排行榜保持一致的 medal-gold/silver/bronze 圆形奖牌
+ // 设计原因：原仅文字色区分（text-yellow/ink/50/orange），与排行榜 Top3 视觉语言不一致；
+ // 复用 medal-* 类让结算弹窗与排行榜同语义（Top3 排名）共享视觉模式
+ const medalBadgeClass = (idx: number) => {
+   if (idx === 0) return 'medal-gold medal-shine text-ink';
+   if (idx === 1) return 'medal-silver medal-shine text-ink';
+   if (idx === 2) return 'medal-bronze medal-shine text-cream';
+   return 'bg-cream text-ink border-2 border-ink/30';
+ };
```

JSX 结构调整：

```diff
- <span className={`font-cn ${medalClass(idx)} ${idx === 0 ? 'font-bold' : ''}`}>
-   {idx + 1}. {p.nickname}
- </span>
- <span className="font-mono font-bold">{p.score} 分</span>
+ <div className="flex items-center gap-2 min-w-0">
+   <div
+     className={`w-7 h-7 rounded-full flex items-center justify-center font-mono font-bold text-xs flex-shrink-0 ${medalBadgeClass(idx)}`}
+     aria-hidden="true"
+   >
+     {idx + 1}
+   </div>
+   <span className={`font-cn text-ink truncate ${idx === 0 ? 'font-bold' : ''}`}>
+     {p.nickname}
+   </span>
+ </div>
+ <span className="font-mono font-bold flex-shrink-0 ml-2">{p.score} 分</span>
```

**设计原因**：
- **同语义同视觉**：排行榜与结算弹窗都是"Top3 排名展示"，语义完全相同，应共享 `medal-*` 视觉模式而非各自一套色相
- **复用既有 CSS 类**：`medal-gold/silver/bronze` 与 `medal-shine` 已在 `index.css` 第 7 轮扩展中定义，无需新增 CSS，仅 JSX 引用
- **`medal-shine` 光泽动画**：Top1/2/3 奖牌缓慢扫过金属高光，强化"领奖台"的仪式感
- **`w-7 h-7` 尺寸克制**：比排行榜的 `w-10 h-10` 小一档，适配结算弹窗密集列表的紧凑布局
- **`aria-hidden="true"`**：奖牌为纯装饰，排名通过 MVP 区域 + 列表顺序朗读，避免冗余
- **`min-w-0` + `truncate`**：长昵称自动截断，避免奖牌被挤压变形
- **`flex-shrink-0` 在分数上**：保证分数始终完整可见，不被昵称挤压

### 2. 任务页 · 奖励 chip 化（tasks.tsx）

**问题**：任务页奖励显示为纯文本"+{reward_exp}经验 +{reward_gold}金币"（右上角小字），视觉层次弱，玩家扫视列表时难以一眼定位奖励数值。挂机页区域信息已用 chip 模式展示（📍区域 / ✨经验 / 💰金币），任务页奖励展示与挂机页 chip 模式脱节。

**修改**：奖励文本改为两个 chip（mint 经验 chip + yellow 金币 chip），垂直堆叠在卡片右上角：

```diff
- <div className="text-right">
-   <p className="font-mono text-xs text-ink/70">奖励</p>
-   <p className="font-mono text-sm text-ink">
-     +{task.reward_exp}经验 +{task.reward_gold}金币
-   </p>
- </div>
+ <div className="flex flex-col gap-1 flex-shrink-0">
+   <div className="bg-mint/15 text-ink px-2 py-0.5 rounded-full font-mono text-xs flex items-center gap-1 border border-mint/30">
+     <span aria-hidden="true">✨</span>
+     <span className="text-mint font-bold">+{task.reward_exp}</span>
+   </div>
+   <div className="bg-yellow/20 text-ink px-2 py-0.5 rounded-full font-mono text-xs flex items-center gap-1 border border-yellow/40">
+     <span aria-hidden="true">💰</span>
+     <span className="text-yellow font-bold">+{task.reward_gold}</span>
+   </div>
+ </div>
```

**设计原因**：
- **色彩语义同源**：mint 经验 chip + yellow 金币 chip 与挂机页区域信息 chip（✨经验 mint / 💰金币 yellow）色彩完全一致，整个应用"经验=mint / 金币=yellow"的色彩语义贯穿
- **chip 边框增强可扫描性**：原纯文本无视觉边界，chip 的 `border-mint/30` / `border-yellow/40` 让奖励数值从卡片背景中"浮出"，玩家扫视列表时一眼定位
- **垂直堆叠适配窄卡**：任务卡右上角空间有限，垂直堆叠比水平排列更稳定，不会因数字位数变化导致布局抖动
- **`flex-shrink-0`**：保护奖励 chip 不被任务名挤压，保证奖励数值始终完整可见
- **`min-w-0` 在中间内容**：让任务名在长文本时优雅截断而非挤压两侧元素
- **复用 ✨ / 💰 emoji**：与挂机页区域信息 chip 的 emoji 完全一致，强化"经验/金币"的视觉符号记忆
- **`aria-hidden="true"` 在 emoji 上**：装饰性 emoji 与后跟文字"+X"语义重复，屏蔽避免屏幕阅读器冗余朗读

### 3. 挂机页 · 武器卡属性 chip 化（idle.tsx）

**问题**：武器卡片底部"攻击: X 暴击: Y% 暴伤: Z%"为内联文本（`flex gap-2` 内的 3 个 span），无视觉层次，玩家难以一眼定位关键属性。挂机页自身区域信息已用 chip 模式展示（📍区域 / ✨经验 / 💰金币），但武器卡属性未跟进同一模式，同一页面内视觉语言不一致。

**修改**：3 个属性改为 3 个小 chip，与挂机页区域信息 chip 模式同源：

```diff
- <div className="flex gap-2">
-   <span className="font-mono text-xs text-ink/60">
-     攻击: <span className="text-orange font-bold">{weapon.base_attack}</span>
-   </span>
-   <span className="font-mono text-xs text-ink/60">
-     暴击: <span className="text-pink font-bold">{(weapon.base_crit_rate * 100).toFixed(0)}%</span>
-   </span>
-   <span className="font-mono text-xs text-ink/60">
-     暴伤: <span className="text-orange font-bold">{(weapon.base_crit_damage * 100).toFixed(0)}%</span>
-   </span>
- </div>
+ <div className="flex gap-2 mb-3 flex-wrap">
+   <div className="bg-orange/15 text-ink px-2 py-0.5 rounded-full font-mono text-xs flex items-center gap-1 border border-orange/30">
+     <span className="text-ink/70">攻击</span>
+     <span className="text-orange font-bold">{weapon.base_attack}</span>
+   </div>
+   <div className="bg-pink/15 text-ink px-2 py-0.5 rounded-full font-mono text-xs flex items-center gap-1 border border-pink/30">
+     <span className="text-ink/70">暴击</span>
+     <span className="text-pink font-bold">{(weapon.base_crit_rate * 100).toFixed(0)}%</span>
+   </div>
+   <div className="bg-orange/15 text-ink px-2 py-0.5 rounded-full font-mono text-xs flex items-center gap-1 border border-orange/30">
+     <span className="text-ink/70">暴伤</span>
+     <span className="text-orange font-bold">{(weapon.base_crit_damage * 100).toFixed(0)}%</span>
+   </div>
+ </div>
```

同时移除原 `<div className="flex gap-2 mt-3">` 上的 `mt-3`，避免与新增 chip 容器的 `mb-3` 形成双重 margin（24px 间距过大）：

```diff
- <div className="flex gap-2 mt-3">
+ <div className="flex gap-2">
```

**设计原因**：
- **同页面同视觉语言**：挂机页区域信息 chip（📍区域 ink / ✨经验 mint / 💰金币 yellow）与武器卡属性 chip 现在共享同一 chip 模式（`bg-{color}/15` + `border-{color}/30` + `rounded-full` + `font-mono text-xs`），整个挂机页视觉语言统一
- **色彩与属性语义对应**：攻击/暴伤用 orange（与挂机页战力展示的"攻击 orange / 防御 mint / 生命 pink"色彩语义一致），暴击用 pink，复用既有色彩映射
- **`flex-wrap` 容错**：3 个 chip 在窄屏宽度不足时自动换行，不会溢出卡片边界
- **`mb-3` 替代 `mt-3`**：chip 容器底部 margin 与按钮行自然分隔，避免双重 margin
- **chip 内"标签 + 数值"结构**：`text-ink/70` 浅色标签 + `text-{color}` 深色数值形成微层次，比原"标签: 数值"内联文本更易扫描
- **保留 emoji-free 设计**：与任务页奖励 chip 不同，武器属性 chip 不加 emoji（属性名"攻击/暴击/暴伤"本身已足够直观），避免装饰过度

## 设计原则总结

本轮遵循以下原则：

1. **视觉一致性补齐 > 新装饰堆砌**：3 处修改的本质都是"已有视觉模式在某些页面未落地"的修复——排行榜已有 medal 奖牌但结算弹窗没有，挂机页区域信息已有 chip 但任务奖励与武器属性没有。补齐后整个应用的视觉语言更统一，而非引入新装饰
2. **同语义同视觉**：排行榜与结算弹窗都是"Top3 排名展示"，应共享 `medal-*` 类；挂机页区域信息与武器属性都是"键值数据展示"，应共享 chip 模式。语义相同的元素用相同视觉模式，是设计系统的基础原则
3. **复用既有 CSS 类**：本轮零新增 CSS 工具类，全部复用前 9 轮已定义的 `medal-gold/silver/bronze` / `medal-shine` 与 chip 模式（`bg-{color}/15` + `border-{color}/30` + `rounded-full`）。CSS 体积增长 0.86 kB 源自构建工具压缩微小变化而非新代码
4. **色彩语义贯穿**：mint=经验/防御、yellow=金币、orange=攻击、pink=暴击/核心——这些色彩语义在前 9 轮已建立，本轮在任务奖励与武器属性上延伸应用，让整个应用的色彩语言更可预测
5. **功能零侵入**：所有修改限于样式层（className、JSX 结构），业务代码一字不动；新增的 `<div>` 均为纯视觉展示，不参与状态管理；`medalClass` 重命名为 `medalBadgeClass` 是内部函数，不影响对外接口
6. **小步增量**：本轮 3 处改动（涉及 3 个文件，零 CSS 新增），每处独立可验证，遵循小步重构原则
